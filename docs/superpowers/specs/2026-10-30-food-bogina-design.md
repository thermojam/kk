# Food Bogina: программная страница «Food-Богиня» — тёмный hero, полный контент

## Статус

Переработано после того, как появился реальный контент (`public/Food-club.pdf`) и два фото
(`public/images/IMG_8463.JPG`, `public/images/photo_cook.jpg`). Три варианта макета собраны и
показаны в артефакте, выбран **Вариант A** — точный повтор ритма `/course/`: тёмный hero с
портретом, тёмный аккордеон тория/практика, финальный CTA-бокс, автор со вторым фото. Эта версия
спеки заменяет версию от 2026-10-30 «подготовка почвы».

## Контекст

Проект уже умеет строить «программные» страницы — `/course/` собрана из:
- `content/course.ts` — типизированный контент;
- `components/course/*` — секции, специфичные для курса;
- общих примитивов (`FAQ`, `ContactCtaBanner`, `TelegramButton`, `Button`, `Badge`, `Accordion`, `ResponsiveImage`);
- целей Метрики в `lib/telegram.ts` (`TG_GOALS`);
- ручной записи в `app/sitemap.ts`.

Вторая программа — «Food-Богиня», курс нутрициолога и шеф-повара (той же Ксении) по
сбалансированному питанию и быстрой готовке. Контент взят из готового PDF-лендинга клиента и
переписан в голос сайта (короче, «ты»-обращение, без маркетинговых повторов оригинала — PDF не
цитируется дословно).

Архитектурное решение не изменилось: **точечная починка существующих связей + явное решение не
строить общий «движок программных страниц»**. Два новых компонента дублируют структуру
`CourseProgram`/`CourseIntro`/`CoursePricing` почти один в один — это сознательно: третьей
программной страницы ещё нет, абстрагировать рано (см. «Явно не делаем»).

## Выбранный макет (Вариант A)

Полный превью: артефакт «Макеты Food-Богиня» (история чата) — вариант A, сейчас единственный
активный. Структура страницы `/food-bogina/`, сверху вниз:

1. **Hero** (тёмный, `bg-dark-gradient`, как у `/course/`) — бейдж «✨ Новая программа», заголовок
   `font-display`, подзаголовок с регалиями автора, lead-абзац, акцентная строка курсивом, факты
   (3 месяца / 1 день на готовку в неделю / эфир раз в неделю), две кнопки (Telegram CTA + якорь на
   `#format`), **портрет-вырез справа** (не фото-карточка — именно плавающий cutout без рамки, как
   десктопный портрет в `CourseHero`).
2. **«Этот курс для тебя, если хочешь»** — сетка из 5 карточек (клон `WorkAreaCard`), по одной на
   каждую причину из PDF-блока «Клуб для вас если хотите».
3. **Теория/практика** — тёмный аккордеон, клон `CourseProgram` (`<details name="...">`, один
   открыт по умолчанию): «Теоретическая часть» (5 пунктов из PDF) и «Практическая часть» (5
   пунктов).
4. **«Курс идёт 3 месяца»** — светлая секция, клон `CourseIntro`: два абзаца + акцентная строка
   курсивом.
5. **«Формат, в каждом месяце» + CTA** — тёмный бокс, клон `CoursePricing`: слева список формата
   (5 пунктов), справа — не цена (её ещё нет), а длительность «3 месяца» + кнопка записи в
   предзапись.
6. **«Автор и ведущая курса»** — список регалий (6 пунктов) + **второе фото-вырез** (`photo_cook.jpg`
   после удаления фона) слева от списка.
7. **Закрывающий акцент** — курсивная цитата + абзац (клон `closingAccent`/`closing` у курса).
8. **`<ContactCtaBanner />`** — переиспользуется как есть, без изменений (тот же баннер и та же цель
   `TG_GOALS.servicesBanner`, что на `/course/` и главной).

FAQ в эту версию не включён: PDF не содержит цену/дату старта, а значит нет материала для
содержательных вопросов про оплату/перенос. Добавится вместе с ценой, когда программа перейдёт из
предзаписи в продажу.

## Явно не делаем

- Не строим общий `components/program/*` слой и общий тип контента программной страницы — решение
  подтверждено повторно: даже при высоком сходстве `CourseProgram`/`FoodBoginaProgram` и
  `CoursePricing`/`FoodBoginaFormat`, абстракция откладывается до третьей программной страницы.
- Не добавляем FAQ на `/food-bogina/` в этой итерации — нет цены/даты, значит нет материала для
  содержательных вопросов. Добавится вместе с ценой.
- Не добавляем форму/виджет стороннего сервиса — CTA остаётся Telegram-диплинком.
- Не добавляем ссылку на `/food-bogina/` в хедер.
- Не удаляем сырые файлы из `public/` прямо сейчас без отдельного подтверждения — только фиксируем
  это как обязательный пункт перед релизом.
