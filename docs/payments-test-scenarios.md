# Платежи: сценарии и тесты

Сводная матрица всех сценариев платёжного модуля (Альфа-Банк API-R) и их
статуса проверки. Архитектура и решения — в
`docs/superpowers/specs/2026-08-09-payments-course-design.md`, здесь только
факт: что проверено, когда и чем подтверждено.

Среда всех прогонов ниже, если не сказано иное, — `ALFA_ENV=test`.

Легенда: `[x]` — прогнано и подтверждено, `[ ]` — не проверено.

## 6. Известно и осознанно не покрыто тестами

- **СБП сквозным платежом** — работоспособен только на проде, тестовый контур
  всегда глушит заявку через ~10 секунд.
- **Callback от банка** (`dynamicCallbackUrl`) — не реализован вообще. Статус
  спрашивается только когда покупатель сам вернулся на сайт.
- **Онлайн-касса ОФД / чек по 54-ФЗ** — не подключены в тестовом контуре,
  `orderBundle` шлюз принимает, но фактическую доставку чека проверить нельзя
  до продуктива.
- **Косметика:** у статуса 3 бейдж и заголовок дословно совпадают
  («Авторизация отменена» дважды) — известно, не считается багом.

## Как читать эту матрицу

Каждая незакрытая строка (`[ ]`) — это либо (а) сценарий, для которого нужен
новый оплаченный тестовый заказ (карта — не переиспользовать заказ дважды на
разных сценариях возврата), либо (б) сценарий, доступный только на боевом
домене/окружении. Перед переключением `ALFA_ENV=prod` актуальный чек-лист
блокеров — по-прежнему в разделе «Чек-лист перед переключением на продуктив»
файла `docs/superpowers/specs/2026-08-09-payments-course-design.md`; этот файл
не дублирует его, а фиксирует именно тестовое покрытие по сценариям.
