# /ui-loop — цикл улучшения визуала

Цель прохода: **$ARGUMENTS**

Три участника с непересекающимися ролями. Роли не совмещать — в этом весь смысл связки.

| Кто | Роль | Отвечает на вопрос |
|---|---|---|
| `impeccable-critique` | прокурор | **что** не так — с доказательством |
| 21st MCP | склад | **чем** чинить — код, темы, направления |
| `impeccable-craft` | редактор | **как** это встроить, чтобы не выглядело сгенерированным |

Критик не чинит. 21st не решает. Craft не выбирает направление.

---

## Фаза 0 · Baseline

Зафиксировать до всего остального:

- **Режим поверхности** — Persuade / Operate / Read / Experience. Берётся из поверхности, а не из продукта.
- **Визитёр и его задача** — одной строкой.
- **Отрендеренное состояние** — десктоп 1440 и мобильный 390, вместе. Реальный контент: длинный, пустой, ошибочный.

Обе шкалы критика судят отрендеренное, а не исходник. Без снятого состояния фаза 1 выродится в чтение кода.

## Фаза 1 · Диагноз

Запустить `impeccable-critique`. Не подсказывать ему выводы и не называть заранее подозрительные места.

На выходе — вердикт, когнитивная нагрузка N/8, эвристики X.X/4, список P0–P3, у каждого пункта доказательство.

**Стоп. Ничего не чинить.** Дождаться выбора скоупа.

## Фаза 2 · Триаж — развилка на 21st

Выбрать скоуп (обычно P0+P1). Каждый выбранный пункт классифицировать по craft §5 — от класса зависит, идём ли мы вообще в 21st:

| Класс находки | Куда |
|---|---|
| **нет токена** — системе нужно переиспользуемое значение | руками в дизайн-систему · опц. `get_theme` |
| **одноразовая реализация** — должен встать общий компонент | → 21st `search` → `get_component` |
| **концептуальное несовпадение** — поток и иерархия расходятся с соседними областями | → 21st `get_inspiration` / `generate` |
| **локальный дефект** — просто недоделано | руками, 21st не трогать |

Только два средних класса оправдывают обращение к каталогу. Установки лимитированы — тратить их на локальные дефекты нельзя.

## Фаза 3 · Материал из 21st

Порядок обращения строгий: **`search` → прочитать код → решить → и только потом тратить установку.**

- `search` + `get_component` — заменить узел проверенным компонентом.
- `get_theme` — когда «нет токена» оказалось системным: шкала отступов, контраст, радиусы.
- `get_inspiration` / `get_take` / `generate` с вариантами — **только** при концептуальном несовпадении, когда нужно направление, а не деталь.
- `iterate_generation` — доводка уже выбранного варианта; дешевле нового `generate`.
- `search_logo`, `search_picker` — точечные дыры.

Бюджет: поиск бесплатный, установок 2 в день, `generate` расходует AI-кредиты.

## Фаза 4 · Карантин ⚠️

**Код из 21st — сырьё, а не результат.** Каталог оптимизирован под «выглядит прилично из коробки», а не под планку craft. Здесь связка чаще всего и ломается.

Прогнать каждый принесённый компонент через craft §2 **до вставки**:

- кикер / eyebrow над заголовком — удалить, это жёсткий запрет;
- градиентный текст → акцент весом или размером;
- цветной `border-left` толще 1px → убрать;
- эмодзи и юникод-глифы → иконки библиотеки проекта, одна толщина штриха;
- вложенные карточки → расплющить;
- 1px-бордер под мягкой тенью → оставить что-то одно;
- хардкод цветов, отступов, радиусов → токены проекта;
- системный display-шрифт → шрифт проекта;
- сетка одинаковых карточек как структура страницы → пересобрать по смыслу.

Компонент не выживает после чистки — он не подходил. Возврат к `search`, а не «допилим потом».

## Фаза 5 · Применение

Загрузить `impeccable-craft`. Чек-лист не проговаривать — применять.

Границы прохода жёсткие:

> собрать полностью → инспектировать **одним** пакетным заходом (десктоп и мобильный вместе) → починить всё найденное **одним** батчем → подтвердить максимум ещё одним заходом → остановиться.

Потолок — два раунда. Открытый self-QA-цикл делает хуже то, что финальное ревью делает лучше.

Отдельно добить браузерные поверхности — каталожные компоненты их почти никогда не несут: `::selection`, `caret-color`, скроллбары, focus-visible ring, `text-underline-offset`, `tabular-nums` в цифрах.

## Фаза 6 · Дельта-ревью

Повторный критик **только по закрытым пунктам**, не полный прогон.

Для каждого: `было` (доказательство из фазы 1) → `стало` (доказательство сейчас) → закрыт / не закрыт.

Новые находки не чинить в этом проходе — записать в бэклог следующей итерации.

---

## Стоп-условия

- все выбранные P0 закрыты с доказательством;
- второй раунд craft не нашёл нового;
- свежие P2/P3 ушли в бэклог, а не в текущий батч.

## Антипаттерны прохода

- Запускать craft до отчёта критика — планка держит механику, но никогда не выбирает направление.
- Давать 21st решать структуру страницы, когда критик не нашёл концептуального несовпадения.
- Чинить молча внутри фазы 1.
- Вставлять компонент из каталога, минуя фазу 4.
- Идти на третий раунд.
- Доводить один угол до идеала, оставив остальное ниже той же планки.
